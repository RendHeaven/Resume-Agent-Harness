# Step 1: Plan — 规格说明

## 目标

在 Interview / Rewrite 之前，基于用户提供的四类材料，生成一份**全面、结构化、可执行**的计划文档，为后续步骤提供统一上下文。

Plan 只做**归纳、对齐、缺口识别**，不改动简历正文，不捏造事实。

## 输入（4 项）

| 输入 | 说明 | 推荐路径 |
|------|------|----------|
| 现有简历 | 用户原始简历，只读 | `resumes/input/<name>.md` |
| 求职方向 | 目标岗位、行业、职级、地域等意向 | `intake/<name>/direction.md` |
| 招聘要求 | JD 全文或结构化要求 | `intake/<name>/requirements.md` | **必填** |
| 现有项目内容 | 简历外补充的项目细节、成果、技术栈 | `intake/<name>/projects.md` |

**`intake/` 与 `resumes/input/` 同为只读区**：由用户创建并维护，Agent **仅读取**，不得创建、覆盖或删除。

用户在聊天中提供的内容，Agent 须给出目标路径与建议格式，**由用户自行保存**到 `intake/` 后再继续；Agent 不得代写 intake 文件。

## 输入门禁（JD 必填）

**招聘要求（JD）为硬性前置条件。** 缺少有效 JD 时，**禁止**进入 Plan 及之后任何步骤。

### 有效 JD 判定

`intake/<name>/requirements.md` 须同时满足：

1. **文件存在**且可读
2. **非空**（去除空白后 ≥ 50 字符）
3. **含实质内容**：至少包含以下之一
   - 岗位职责 / 工作职责 / Responsibilities
   - 任职要求 / 岗位要求 / Requirements / Qualifications
   - 可识别的技能/年限/学历等硬性条目（≥ 2 条）

以下情况视为 **无效 JD**，等同缺失：

- 文件不存在
- 仅含占位符（如「待补充」「TBD」「未提供」）
- 仅有一句话方向（如「找后端工作」）而无具体招聘要求

### 缺失时的 Agent 行为

1. **立即停止**，不生成 `plans/` 文件
2. **明确告知**用户：缺少 JD，无法继续
3. **引导补充**：请用户自行创建或更新 `intake/<name>/requirements.md`（可粘贴 JD 全文；Agent 可提供格式化建议，但**不得代写文件**）
4. **等待用户补充**后，重新执行门禁检查，通过后方可进入 Plan

**禁止**用「未提供」「暂无 JD」等占位完成 Plan 的「招聘要求总结」章节。

## 输出

| 产物 | 路径 | 说明 |
|------|------|------|
| 计划文档 | `plans/YYYY-MM-DD-<name>.md` | 三大章节 + 后续指引 |

模板见 [docs/templates/plan-template.md](templates/plan-template.md)。

## 执行流程（含思维链）

```text
① JD 门禁
    ↓ 未通过 → 停止，引导用户补充 requirements.md
② 读取四类输入（只读）
    ↓
③ 思维链推演（在聊天中展开，并写入 Plan「零、思维链」）
    ↓
④ 方向校验 → 发现阻塞级问题？
    ├─ 是 → 聊天中反问，暂停 Plan 落盘，等用户澄清并更新 intake/
    └─ 否 → 继续
⑤ 写入 plans/YYYY-MM-DD-<name>.md（三大章节 + 后续指引）
    ↓
⑥ 存在非阻塞待确认项？→ 标记 Plan 状态，禁止进入 Step 2 直至用户确认
```

## 思维链（Chain of Thought）

Plan **必须**包含「零、思维链」章节，记录 Agent 从输入到结论的推理过程，供用户 Review 与后续步骤引用。

### 必须覆盖的推演步骤

| 步骤 | 内容 |
|------|------|
| **输入理解** | 四类材料各自提供了什么关键信息；哪些字段缺失 |
| **方向三角对齐** | 分别提取 direction、JD、resume 中的「目标岗位 / 职级 / 赛道」，并排对照 |
| **矛盾与疑点识别** | 列出不一致、模糊、无依据之处，标注严重度 |
| **推演结论** | 基于上文，进入三大章节前的核心判断（一句话 + 3 条以内要点） |

### 写作要求

- 逐步推理，**写「因为 A，所以 B，但 C 与 B 矛盾」**，不得跳步直接给结论
- 引用具体来源（`direction.md` 第 X 节 / JD 原文 / 简历某段）
- 不得捏造输入中不存在的信息来填补推理链

## 方向校验与反问

在思维链第 ③④ 步，Agent 须主动检查 **direction × JD × resume** 三者是否在「求职方向」上自洽。发现下列 **阻塞级** 问题时，**必须立即在聊天中反问**，并 **暂停 Plan 落盘**：

| 阻塞级问题 | 示例 |
|------------|------|
| **direction 与 JD 岗位类型冲突** | direction 写「前端负责人」，JD 为「Java 后端」 |
| **多个互斥 P0 方向** | 同时 P0「算法」与 P0「产品经理」且无主次说明 |
| **direction 缺失或无有效 P0** | `direction.md` 不存在，或仅有「想找好工作」 |
| **简历主赛道与 direction 严重不符** | 简历全栈后端 5 年，direction 写「财务岗」且无转型说明 |
| **职级定位与 JD 硬性要求明显矛盾** | JD 要求 8+ 年架构师，direction/resume 整体呈现 2 年 junior 且无说明 |
| **JD 与 direction 地域/行业硬性约束冲突** | direction 写「仅远程」，JD 写「必须 onsite 上海」 |

### 反问行为

1. **一次性列出**所有阻塞级问题（≤ 5 条），每条附：**矛盾点 + 涉及材料 + 建议用户如何澄清**
2. **暂停** Plan 落盘，**禁止**进入 Step 2 Interview
3. 引导用户**自行更新** `intake/<name>/direction.md`（Agent 不得代写）
4. 用户澄清后，Agent **重新执行** 思维链与方向校验，通过后再落盘

### 非阻塞疑点

以下情况 **不强制暂停**，但须写入 Plan「零、思维链 → 待确认项」并在聊天中轻量提醒：

- 行业 / 地域 / 公司类型偏好未提供
- P1 备选方向与 P0 有关联但不互斥
- 匹配矩阵中多项「弱 / 无依据」但方向本身清晰

存在非阻塞待确认项时，Plan 元信息 `状态` 标为 `待确认`；用户确认前 **禁止** 进入 Step 2。

## 输出章节要求（必须全面）

### 0. 思维链（新增，位于最前）

见上文「思维链」与模板 `零、思维链` 节。

### 1. 求职意向总结

必须覆盖：

- 目标岗位名称与方向（可多选，标注优先级）
- 职业阶段定位（如：3 年后端 / 转管理 / 校招）
- 行业、地域、公司类型等偏好（**仅写用户明确提供的**）
- 当前简历与意向方向的初步差距（基于材料，不下结论性编造）

### 2. 现有项目信息总结

必须覆盖：

- 项目清单表：名称、时间、角色、团队规模（若有）、技术栈
- 每个项目的：背景、个人职责、成果、难点（**均来自简历或 projects 补充**）
- 可挖掘亮点（哪些经历适合后续突出）
- 信息缺口清单：缺量化、缺技术细节、描述模糊 → 标记 `[待补充: ...]`

### 3. 招聘要求总结

必须覆盖：

- 硬性条件：学历、年限、必备技能、证书等
- 软性要求：沟通、协作、业务、领导力等
- ATS 关键词与能力模型（从 JD 提取，分组列出）
- 匹配矩阵：每条核心要求 ↔ 现有经历（强 / 中 / 弱 / 无依据）

### 4. 后续步骤指引（Plan 独有）

为 Step 2 Interview 提供：

- Interview 应重点核验的 3–5 条 JD 条目
- Rewrite 应优先突出的 2–3 段经历
- 需用户补充的信息清单（汇总各章 `[待补充]`）

## 事实边界

- **禁止**在 Plan 中捏造公司、项目、成果、技能、年限
- 材料未提及的内容写「未提供」或「无依据」，不得推测为事实
- 匹配矩阵中「弱 / 无依据」必须如实标注，不得为好看而夸大

## DoD（完成定义）

- [ ] **JD 门禁已通过**（`requirements.md` 有效，见上文判定标准）
- [ ] **思维链章节已写入**，含方向三角对齐与推演结论
- [ ] **无未解决的阻塞级方向问题**（有则已反问并暂停，不得落盘）
- [ ] 若存在非阻塞待确认项，Plan 状态为 `待确认` 且已在聊天提醒
- [ ] 其余三类输入均已落盘（简历必填；direction / projects 缺失时须用户确认并记录）
- [ ] `plans/YYYY-MM-DD-<name>.md` 已创建
- [ ] 三大章节均非空，且各含规定子节
- [ ] 匹配矩阵至少覆盖 JD 中 80% 的核心要求
- [ ] 后续步骤指引已写入
- [ ] 未修改 `resumes/input/` 原文

## 触发示例

```
按 resume-agent skill 执行 Step 1 Plan：
- 简历：resumes/input/zhangsan.md
- 求职方向：intake/zhangsan/direction.md
- 招聘要求：intake/zhangsan/requirements.md
- 项目补充：intake/zhangsan/projects.md
```

## 与后续步骤的关系

```text
Plan（本步）
  ↓ plans/YYYY-MM-DD-<name>.md
Interview（Step 2）
  ↓ reviews/YYYY-MM-DD-<name>.md + .json  ← 系统提示词驱动，只读 input 简历
Rewrite（Step 3）
  ↓ resumes/output/<name>.md
Eval（Step 4）
    ↓ evals/runs/... panel_passed
Gap（Step 5）
    ↓ gaps/YYYY-MM-DD-<name>.md  ← 技能不足与改进建议，任务完成
```

**禁止**跳过 Plan 直接进入 Interview 或 Rewrite。

**禁止**在无有效 JD 时生成 Plan 或进入后续步骤。
