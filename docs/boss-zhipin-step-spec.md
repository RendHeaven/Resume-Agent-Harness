# Step 6: Boss直聘在线简历输出规格

## 目标

基于已通过 Step 4 全票评测的 `resumes/output/<name>.md` 定稿，结合 Step 5 Gap 报告，输出 **Boss直聘平台专用在线简历内容**。

Boss直聘与 Markdown 简历的核心差异：平台按字段结构化采集内容，每个字段有独立的 HR 观感权重；字段之间必须形成**递进逻辑链**，而非平铺式职责列举。

## 前置条件

- Step 4 `panel_passed === true`
- `resumes/output/<name>.md` 存在
- `gaps/YYYY-MM-DD-<name>.md` 存在（Step 5 已完成）

## 必读模板

`docs/templates/boss-zhipin-template.md` — 字段设计规范、公式与反例

## 核心设计原则

### 递进逻辑链（不得平铺）

```
职位名称（角色定位·层级信号）
    ↓  引出战场
工作内容（1 行锚定句：我打的是什么规模的仗？）
    ↓  证明战绩
工作业绩（3-5 条数字暴击：我赢了什么？按影响力由大到小排序）
    ↓  亮出武器
拥有技能（精选技术关键词：我用什么打赢的？与 JD 对齐）

    ↓  HR 产生兴趣，主动下探

项目名称（关键词嵌入：这场仗叫什么名字？）
    ↓  设置悬念
项目描述（背景痛点1句 + 机制钩子2-3条：怎么打的，留细节白）
    ↓  量化爆锤
项目业绩（纯数字对比：赢了多少？维度标签 + before→after）
```

**禁止**：把职责列表放进工作业绩；把数字成果放进工作内容；工作业绩为空。

### HR 扫描策略（7 秒原则）

| 时间 | HR 视线落点 | 我们的应对 |
|---|---|---|
| 0-1s | 职位名称 + 公司名 | 职位名称必须精确，不用「负责人」等模糊词 |
| 1-3s | 工作业绩第一条 | 最大影响力数字必须在第一条 |
| 3-5s | 项目名称 + 项目业绩头两条 | 项目名嵌关键词；业绩第一条最大数字 |
| 5-7s | 拥有技能标签 | 仅列 JD 命中词，不堆砌 |

## 字段公式

### 工作内容（≤100 字）

```
在 [业务规模/技术背景] 中，作为 [角色定位]，
主导 [核心职责范围]；核心目标是 [可量化目标或核心命题]。
```

> 只定义战场规模和你的角色，**不写成就**。成就在业绩里。

### 工作业绩（3-5 条，每条 ≤ 40 字）

```
[强动词] [机制/方法]，[指标名称] [提升/下降] [数字]（[对比基准]）
```

**排序原则**：
1. 第一条：规模最大、改进幅度最惊人的数字
2. 第二条：核心技术能力证明
3. 第三-五条：影响力扩散（跨部门/团队/成本维度）

**强动词库**：主导、设计、构建、搭建、重构、落地、主攻、牵引、驱动、压缩、归零

**禁止弱动词**：参与、负责、协助、完成、承担

### 拥有技能（精选，不堆砌）

- 按「主技能 → 工具 → 方法论」排序
- 只列与该岗位 JD 强相关的词
- 每段工作经历的技能词不得完全相同（体现成长）

### 项目名称（嵌关键词）

```
[公司缩写·项目核心定性词]（[角色]）
```

> 项目名中嵌入 JD 高频关键词（ATS 优化），面试官看到名字就知道这个项目的分量。

### 项目描述（≤150 字）

```
[痛点背景：规模 + 问题 + 影响，1 句话]。
· [机制1：强动词 + 核心术语 + 留白，不展开HOW]
· [机制2：强动词 + 核心术语 + 留白]
· [机制3：规模数据 or 覆盖范围]
```

> 项目描述 = 背景交代 + 技术钩子。**禁止**把量化数字放进描述，数字归业绩。

### 项目业绩（4-6 条，每条 ≤ 30 字）

```
[维度标签]：[before] → [after]（[增幅或说明]）
```

**排序**：改进幅度最大 → 效率类 → 质量类 → 规模类 → 其他

## 输出路径

| 产物 | 路径 | 说明 |
|---|---|---|
| 内容文档 | `resumes/output/<name>-boss.md` | 按字段分块，可直接复制到 Boss直聘 |

## DoD

- [ ] 工作内容为锚定句（≤100 字），不含成就数字
- [ ] 工作业绩第一条为最大影响力数字
- [ ] 项目名称嵌入 JD 核心关键词
- [ ] 项目描述含背景 + 机制钩子，量化数字全部移至项目业绩
- [ ] 无弱动词（参与/负责/协助/完成）
- [ ] 所有数字与 `resumes/output/<name>.md` 及 `intake/<name>/projects.md` 一致，无捏造

## 禁止

- 捏造未在 output 简历或 projects 补充中出现的数字或项目
- 将职责列表放进业绩字段（误以为越多越好）
- 拥有技能堆砌与该段经历无关的工具
- 项目描述写成职责说明书（应写机制钩子，引发追问）
